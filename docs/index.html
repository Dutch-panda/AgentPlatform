01 / Workflow

A role for every stage.

Natasha chooses the starting point. The selected route runs sequentially through implementation, with explicit validation commands for each phase.

Meti

Implements through Docker commands, retries failed phase checks within a fixed limit, and records validation history.

BUILD & VALIDATE

This is the full route. Clearer tasks can skip research or design; the runtime still selects the appropriate route.

  • Research-led requestNatasha → Odin → Taghi → Meti
  • Architecture-led requestNatasha → Taghi → Meti
  • Direct implementationNatasha → Meti

Completion has a gate.

Meti must submit each phase’s exact validation command, in order. Each phase allows three validation attempts per run, with repair commands between checks. A third failure stops execution; any unvalidated phase prevents success.

Checks record command exit codes. Review the generated code and tests before relying on the result.

03 / Checkpoints & resume

Pick up where work stopped.

A permanent task ID connects the saved prompt, project, stage outputs, and phase history. The local SQLite ledger records progress in .state/tasks.db.

RESUME · SAME REPOSITORY ROOT
# Replace this example with your saved task ID
python main.py --resume \
  task-20261024-build-csv-012345abcdef

Reuse the saved prompt and project. Do not combine --resume with a new prompt or --project.

Keep completed work.

Saved briefs, research, and specifications are reused. Validated phases stay completed; unfinished phases receive three validation attempts in the resumed run. Previous attempt history remains in the review note.

Keep local files together.

Back up .state/, the task workspace, and vault/ while no task is running. These local artifacts are not all backed up by Git. A completed task returns without rerunning agents.

An interrupted command may have partially completed and may run again. Inspect its files, running containers, and side effects first. Resume starts a fresh model conversation with saved context; it cannot restore a lost workspace.

04 / Quick start

Start with a task.

Use Python 3.11+ with Docker running and ChatGPT model access. Run from the repository root; the first workflow prompts for OAuth sign-in.

TERMINAL · macOS / Linux
# Clone and install
git clone https://github.com/Dutch-panda/AgentPlatform.git
cd AgentPlatform
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
docker info

# Run a task with a shared project ID
python main.py "Build a CSV validation utility" --project csv-tools

Resume a saved task with python main.py --resume <task_id>. Completed stages and validated phases are reused; unfinished phases get a fresh retry budget. Generated source lives in workspace/<task_id>/. Stage notes live in vault/. See the README for Windows activation, configuration, and troubleshooting.

06 / Current boundaries

Know what runs today.

An early platform with explicit constraints. These details help you interpret its output and plan a run.

Research uses vault context, without dedicated web search.

Odin has vault graph tools. It has no dedicated live web-search tool, so reports are not evidence of verified current external research. Related vault sources identify retrieved graph context, without claiming that full notes were read or each finding was verified.

Docker commands start in fresh containers.

Only the task directory is mounted. Files there persist, but container-local installs do not. The default image is Node 18; other runtimes are not provisioned by the runner. Network access is enabled, without configured CPU or memory limits.

Resume needs the local ledger and workspace.

Run from the same repository root. Unknown task IDs, invalid checkpoints, and a missing workspace after implementation begins cause resume to fail. Older tasks without ledger records are not imported automatically. Per-task process locks prevent concurrent CLI runs; an interrupted command may run again.

Some artifact links can be unresolved.

New routing briefs use permanent task IDs. Notes may still link to stages that were skipped, and historical notes can contain temporary task links.

Validation is based on exit codes.

Passing phase commands does not independently establish test quality. The platform has deterministic unit tests with mocked services; live model behavior and Docker execution require separate checks. GitHub Actions runs the platform tests on pushes and pull requests using Python 3.11 and 3.14. Natasha’s optional note-writing tool also references an uninitialized research directory; see the README for the documented limitation.
