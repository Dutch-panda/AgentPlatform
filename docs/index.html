01 / Workflow

A role for every stage.

Natasha chooses the starting point. The selected route runs sequentially through implementation, with explicit validation commands for each phase.

01 →

Natasha

Frames the objective with a 5-sentence brief, routes the task, and resolves ambiguities via a clarification wizard.

COORDINATE
02 →

Odin

Queries vault context, looks up package metadata on PyPI/npm, and retrieves documentation search snippets with URL checks.

RESEARCH
03 →

Taghi

Defines architecture, dependencies, and ordered execution phases.

DESIGN
04 ↗

Meti

Implements through Docker commands with live progress spinners, validates phases, generates workspace READMEs, and tracks token usage.

BUILD & VALIDATE

This is the full route. Clearer tasks can skip research or design; the runtime still selects the appropriate route.

  • Research-led requestNatasha → Odin → Taghi → Meti
  • Architecture-led requestNatasha → Taghi → Meti
  • Direct implementationNatasha → Meti

Completion has a gate.

Meti must submit each phase’s exact validation command, in order. Each phase allows three validation attempts per run, with repair commands between checks. A third failure stops execution; any unvalidated phase prevents success.

Checks record command exit codes. Review the generated code and tests before relying on the result.

02 / Project memory

Keep the work connected.

Reuse a project ID to connect related notes and workspaces. Tasks sharing a project ID use the same workspace (workspace/<project_id>/), building directly on existing codebase files; standalone tasks use workspace/<task_id>/. Project links group related artifacts.

Task briefsResearch reportsSpecificationsImplementation reviews
→
Shared project note

vault/projects/<project_id>.md

Browse Markdown and wikilinks in Obsidian. Graphify adds node and connection lookup when extraction is available. Research reports link to existing vault notes resolved from retrieved context.

Graph extraction is optional in practice: failed updates log a warning while saved Markdown remains available.

03 / Checkpoints & resume

Pick up where work stopped.

A permanent task ID connects the saved prompt, project, stage outputs, and phase history. The local SQLite ledger records progress in .state/tasks.db.

RESUME · SAME REPOSITORY ROOT
# Replace this example with your saved task ID
python main.py --resume \
  task-build-csv-20261024

Reuse the saved prompt and project. Do not combine --resume with a new prompt or --project.

Keep completed work.

Saved briefs, research, and specifications are reused. Validated phases stay completed; unfinished phases receive three validation attempts in the resumed run. Previous attempt history remains in the review note.

Keep local files together.

Back up .state/, the task workspace, and vault/ while no task is running. These local artifacts are not all backed up by Git. A completed task returns without rerunning agents.

An interrupted command may have partially completed and may run again. Inspect its files, running containers, and side effects first. Resume starts a fresh model conversation with saved context; it cannot restore a lost workspace.

04 / Quick start

Start with a task.

Use Python 3.11+ with Docker running and a configured API provider, ChatGPT OAuth, or compatible local model. Run from the repository root; the setup wizard helps configure access.

TERMINAL · macOS / Linux
# Clone and install
git clone https://github.com/Dutch-panda/BuildRelay.git
cd BuildRelay
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
docker info

# Run interactive onboarding wizard
buildrelay config

# Run a task with a shared project ID
buildrelay "Build a CSV validation utility" --project csv-tools

Resume a saved task with python main.py --resume <task_id>. Completed stages and validated phases are reused; unfinished phases get a fresh retry budget. Generated source lives in workspace/<project_id>/ (or workspace/<task_id>/ for standalone tasks). Stage notes live in vault/. See the README for Windows activation, configuration, and troubleshooting.

06 / Verification

Check the platform locally.

Unit tests isolate external services. Opt-in smoke checks exercise real infrastructure without calling live models. Run these commands from the repository root after activating your virtual environment.

TERMINAL · TESTS
# Install test dependencies and run the default suite
python -m pip install -e '.[test]'
python scripts/validate.py

# Opt in to real Docker and Graphify smoke checks
BUILDRELAY_INTEGRATION=1 python -m pytest -m integration -v

# Or select one integration service
BUILDRELAY_INTEGRATION=1 python -m pytest -m docker
BUILDRELAY_INTEGRATION=1 python -m pytest -m graphify

Integration tests skip by default. When enabled, checks also skip if their Docker daemon or Graphify CLI is unavailable; a skipped check is not a verified pass. Docker checks may download python:3.11-slim, configurable with DOCKER_SMOKE_IMAGE. Graphify checks cover Python symbol extraction, queries, and incremental updates—not Markdown research quality. These checks do not assess live model behavior or generated application correctness.

07 / Current boundaries

Know what runs today.

An early platform with explicit constraints. These details help you interpret its output and plan a run.

Interactive onboarding wizard simplifies provider setup.

BuildRelay provides python main.py config (or buildrelay config) to guide provider selection, masked credential entry with reachability checks, model tiers, and lead overrides, persisted safely to .env with mode 0600.

Model tiers, cache settings, and context pruning are configurable.

Provider-specific tiers and per-lead overrides select models for each role. Context pruning reduces supplied content. Cache settings are passed to the SDK; cache hits and latency or cost savings depend on provider support and are not guaranteed.

Alignment gate confirms intent before execution.

Natasha produces a 5-sentence brief and prompts with a clarification wizard for ambiguous requirements. Pressing Enter accepts recommended defaults, and -y / --auto enables unattended headless runs. Mid-way pivots roll back downstream checkpoints safely.

Token consumption and estimated USD costs are tracked per lead.

Reported prompt and completion tokens come from PydanticAI metrics. Costs use a bundled rate table and approximate cache discounts; they are not billing records. Local models display zero estimated API cost. Metrics are reported in inline terminal badges, code review notes, and a final summary table.

Docker runs display live spinners and deliver clean workspaces.

Container execution logs are written to .state/task.log to keep terminal output readable. A fallback workspace README is created when missing or empty; existing nonempty READMEs are preserved. The CLI displays a file tree and How to Run banner. Review generated instructions before use.

Web and documentation search includes SSRF guardrails and token budgeting.

Odin and Natasha retrieve search snippets; Odin records result URLs and has three search calls per research invocation. URL checks block selected local hostnames and literal private IPs but do not resolve DNS or revalidate redirects. A page-extraction helper exists but is not an agent tool. Registry lookup does not establish package safety, and offline lookup can currently be labeled verified. Cached searches have no expiry.

Specifications are prompted to use actionable sandbox checks.

Taghi is instructed to put missing credentials and deployment prerequisites in architecture notes rather than executable phases. This is model guidance, not an enforced offline execution policy; Docker networking remains enabled.

Host API keys and credentials are isolated from containers.

Host environment variables (such as OPENAI_API_KEY, ANTHROPIC_API_KEY, or GEMINI_API_KEY) are never passed into Docker containers. Containers mount the task or shared project workspace; the runner does not mount the repository root, .env, or .state/. This mount configuration is not a guarantee against hostile code. Keep sensitive files out of generated workspaces.

Model-callable note tools constrain write destinations.

Model-callable note tools use shared path-contained Markdown writers. Application-generated stage artifacts also use direct writes to configured directories; the shared writer does not mediate every artifact write.

Docker commands start in fresh containers.

Only the project or task directory is mounted. Files there persist, but container-local installs do not. The default image is Node 18, but runtime-specific images (e.g. python:3.11-slim) can be selected via --image, DEFAULT_SANDBOX_IMAGE, or within Taghi’s technical specification. Network access is enabled, without configured CPU or memory limits.

Multiple model providers and direct API keys are supported.

Use standard API keys (OPENAI_API_KEY, ANTHROPIC_API_KEY, GEMINI_API_KEY) or specify models with --model (e.g., openai:gpt-4o, anthropic:claude-3-5-sonnet-latest), with automatic fallback to ChatGPT OAuth if no API keys are present.

Resume needs the local ledger and workspace.

Run from the same repository root. Unknown task IDs, invalid checkpoints, and a missing workspace after implementation begins cause resume to fail. Older tasks without ledger records are not imported automatically. Per-task process locks prevent concurrent runs of the same task. Different tasks sharing a project workspace are not locked against each other; avoid concurrent edits. An interrupted command may run again.

Some artifact links can be unresolved.

New routing briefs use permanent task IDs. Notes may still link to stages that were skipped, and historical notes can contain temporary task links.

Automated checks include isolated unit tests and real integration smoke checks.

The default suite uses mocked external services and skips integration checks. Enable BUILDRELAY_INTEGRATION=1 for real Docker and Graphify checks; missing infrastructure causes skips. GitHub Actions runs both suites on Python 3.11 and 3.14. Check the run results for passes, skips, and failures. Passing checks do not establish generated test quality or replace code review.
